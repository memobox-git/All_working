1ETL vs ELT. When do you pick each?
Answer
  • ETL: transform first, then load. Good when data must be cleaned or masked before it lands.
  • ELT: load raw, transform inside the warehouse (Snowflake, BigQuery, Databricks).
  • Most modern stacks are ELT with dbt or Spark.
  • Say why you chose one in your last project.
2Walk me through a pipeline you've built, end to end.
Answer
  • Source → ingest → raw → clean → serve
  • Volume, frequency and the tool at each step
  • How it fails and how you recover
  • Who uses the output and for what
  • One number that proves the impact
Tell it like a story

4A Spark job is slow. Where do you start?
Answer
  • Open the Spark UI. Find the slowest stage.
  • One task 10x slower? Skew. Salt the key or use AQE.
  • Huge shuffle? Broadcast the small table.
  • Thousands of tiny files? Compact them.
  • Only then add more nodes.
5How do you build an incremental load?
Answer
  • Keep a watermark (e.g. updated_at) in a control table
  • Read only rows newer than the watermark
  • MERGE (upsert) them into the target
  • Handle deletes: soft delete or CDC
  • Rerun-safe: two runs, same result
6Parquet, Avro, JSON or CSV?
Answer
  • Parquet: columnar and compressed. Best for analytics.
  • Avro: row-based with a schema. Common with Kafka.
  • JSON: flexible and nested, but big and slow to scan.
  • CSV: simple, but no types and no schema.
7Your pipeline ran twice. How do you avoid duplicates?
Answer
  • Make every write idempotent
  • MERGE on a business key, not a plain INSERT
  • Or overwrite the whole partition for that day
  • Dedupe with ROW_NUMBER() over key, latest timestamp first
8What do Delta Lake and Iceberg add to Parquet?
Answer
  • ACID transactions: no half-written tables
  • Schema enforcement and evolution
  • Time travel to older versions
  • MERGE, UPDATE and DELETE on lake files
Lake + ACID = lakehouse
9A query on 1B rows is slow. What do you check?
Answer
  • Read the plan (EXPLAIN)
  • Filter early. Select only the columns you need.
  • Partition or cluster on the filter column so files get skipped
  • Duplicate join keys? Rows explode.
10What goes wrong with joins?
Answer
  • Duplicate keys multiply rows
  • NULL never equals NULL, so those rows vanish in an inner join
  • LEFT JOIN + a WHERE on the right table acts like an inner join
  • Compare row counts before and after
11How do you handle late-arriving data?
Answer
  • Process by event time, not load time
  • Reprocess a lookback window (e.g. last 3 days)
  • Use watermarks in streaming (Spark, Flink)
  • Late customer record? Load an "unknown" row, fix it later.
12Scenario: 1 TB lands every day. Design it.
Answer
  • Land raw files in S3 / ADLS / GCS
  • Store as Parquet or Delta, partitioned by date
  • Process only the new day
  • Run quality checks before publishing
  • Watch run time, cost and freshness
