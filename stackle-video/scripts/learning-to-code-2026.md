## Part 1: What AI tools can really do today

**[Graphic 2, full screen]**
[pause]
Writing software with AI is now normal. In the 2025 developer survey by Stack Overflow, the question-and-answer site for programmers, eighty-four percent of developers said they use AI tools or plan to start. Google says that about three quarters of its new code is now generated by these tools and then approved by its engineers.
[pause]

**[On camera]**
The most important word in Google's statement is "approved". Before an engineer approves code, that engineer has to read it and decide whether it is right. AI tools made typing fast, but they did not make checking fast, and checking needs someone who knows how to code.

**[Graphic 3, full screen]**
[pause]
The 2025 Stack Overflow survey also shows why checking matters. The most common frustration, named by sixty-six percent of developers, is AI answers that are almost right, but not quite. More developers distrust the accuracy of AI tools than trust it, forty-six percent against thirty-three percent.
[pause]

**[Graphic 4, full screen]**
[pause]
An almost-right answer works like autocorrect on your phone. Autocorrect changes one word into another real word, so the message still looks fine, but it now says something you did not mean.
[pause]

**[Graphic 5, full screen]**
[pause]
In data engineering, code that is almost right is more dangerous than code that is broken. A broken program stops with an error, so you notice. An almost-right program runs to the end and hands you a wrong number, and nothing tells you it is wrong.
[pause]

**[Graphic 6, full screen]**
[pause]
Here is a common example from SQL, the language used to ask questions of a database. Each question is called a query, and a join is how a query combines two tables. Suppose you join orders to payments, and one customer paid for a purchase in two parts. That purchase now shows up twice, the result comes back without an error, and the revenue report shows more money than the company made.
[pause]

**[On camera]**
Catching a wrong number before anyone uses it is the real reason to learn to code in 2026. You will never type faster than an AI tool, and you do not need to. You need to know enough to see when the tool's answer is wrong, before someone makes a business decision with it.

## Part 2: What the job numbers say

**[On camera]**
If reading and checking code is the skill that matters, the next question is whether companies still pay people to do it. The job numbers are mixed, so here is the honest version.

**[Graphic 7, full screen]**
[pause]
The US Bureau of Labor Statistics published new ten-year projections in August 2026. Between 2025 and 2035, jobs for software developers are expected to grow by ten percent. Jobs for data scientists, who use data to find patterns and make predictions, are expected to grow by thirty-five percent. If you have heard fifteen or seventeen percent for software developers, those numbers come from older projections.
[pause]

**[Graphic 8, full screen]**
[pause]
Entry-level hiring is where the news is harder. Researchers at Stanford use payroll records to track employment. In their August 2026 update, workers aged twenty-two to twenty-five in the jobs most exposed to AI had fallen nineteen percent behind others their age in jobs less exposed to AI. The researchers found that the gap comes mostly from companies hiring fewer young people, not from firing them.
[pause]

**[Graphic 9, full screen]**
[pause]
Job postings show that companies now want experience. Indeed's Hiring Lab reports that, in August 2026, software development postings in the United States were still about twenty-six percent below their February 2020 level. Demand has started to grow again, but seventy-one percent of the growth between May 2025 and May 2026 came from senior roles. Thirty-seven percent of that growth came from jobs with AI in the title.
[pause]

**[On camera]**
Taken together, the job numbers give an honest picture. Coding work is not disappearing, and the roles connected to data and AI are growing. The first job, though, is harder to get than it was five years ago, because companies expect a new engineer to be useful sooner. You get past that with proof that you can do the work, and part four of this video shows you how to build it.

## Part 3: The coding skills that matter less and the ones that matter more

**[On camera]**
AI has changed which coding skills are worth your time. When I interview engineers today, I care less about how fast someone writes code and more about whether they understand it.

**[Card beside you]** Card: "Matters less: memorizing syntax, writing boilerplate, small scripts from scratch"
Three coding skills matter less than they used to. The first is memorizing syntax, which means the exact spelling and order of commands, like the code that formats a date. An AI tool or the documentation gives you that in seconds. The second is writing boilerplate, which is the setup code every project repeats, such as the lines that connect a program to a database. The third is writing small scripts, which are short programs, from scratch. A script that renames a folder of files is one example, and AI tools usually get those right on the first try.

**[Graphic 10, full screen]**
[pause]
Reading code is now the most important coding skill. It means you can look at a SQL query or a function and say what it will return before you run it. A function is a named block of steps that does one job, like adding tax to a price.
[pause]

**[Graphic 11, full screen]**
[pause]
Data modeling matters more than before. Data modeling means deciding how tables are designed and connected, like deciding that every order must belong to exactly one customer. An AI tool will build any table you ask for, but a person who knows the business has to decide which design is right.
[pause]

**[Graphic 12, full screen]**
[pause]
Testing matters more, because AI tools produce more code than anyone can read line by line. A test is a small check that proves an answer is right. In the orders and payments example from earlier, a test could compare the revenue report's total with the total in the payments table, and fail if the two numbers differ.
[pause]

**[Graphic 13, full screen]**
[pause]
System design matters more, because it is where AI tools need the most guidance. System design means deciding how the parts fit together, such as where the data is stored, how often it updates, and what happens when one step fails. Planning a kitchen works the same way: you decide where the sink and the stove go before you buy them.
[pause]

**[Graphic 14, full screen]**
[pause]
LinkedIn ranked AI engineer first on its list of the fastest-growing jobs in the United States, in both 2025 and 2026. If you want to become an AI engineer, add one more skill to the list, which is evaluation. Evaluation means measuring how often your system gives the right answer. For example, you can ask a support chatbot one hundred real customer questions and count how many answers are correct.
[pause]

**[On camera]**
In my interviews, one question tells me the most. I show a short piece of code and ask, "What does this do, and what could go wrong?" An engineer who can answer that question well is useful with AI and without it.

## Part 4: How to learn to code in 2026

**[On camera]**
Now that you know which skills matter, here is how I would learn them in 2026 without letting AI do the thinking for me.

**[Graphic 15, full screen]**
[pause]
If you want to become a data engineer or an AI engineer, start with SQL and Python. SQL is how you ask questions of a database, and Python is the main language for data and AI work. You do not need five languages. You need these two, learned well.
[pause]

**[Card beside you]** Card: "1. Try it first, then ask AI"
When you practice, try each problem yourself before you ask an AI tool. Then ask the tool for its version and compare the two. The answers at the back of a math textbook work the same way: they help after you try, but they teach you nothing if you read them first.

**[Card beside you]** Card: "2. Never keep code you cannot explain"
Never keep a line of code you cannot explain. If an AI tool writes something you do not understand, ask it to explain that part. Then close the chat and write it again in your own words.

**[Card beside you]** Card: "3. Check the answer, not just the code"
Check that the answer is right, not just that the code runs. For every query you write, add one check that would catch a wrong number, like counting the rows before and after a join. If one row turns into two, you have found the doubled revenue before anyone else sees it.

**[Graphic 16, full screen]**
[pause]
Build one project from start to finish instead of watching ten tutorials. For data engineering, take free public weather records, store them in a database, clean them with SQL, and show them on a dashboard, which is a page of charts. For AI engineering, add a chatbot that answers questions about that data, then measure how often it is right. A finished project gives an interviewer something real to ask you about.
[pause]

**[On camera]**
So, is learning to code still worth it in 2026? Yes, if you learn to read, check, and design code, and not only to type it. AI made typing cheap, and that made understanding more valuable.
