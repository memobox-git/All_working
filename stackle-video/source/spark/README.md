# Apache Spark, Explained in 2 Minutes (episode 04)

A 1:55 explainer on a white canvas, with Spark's orange as the accent. It is voiced by the ElevenLabs "Crispus Roshan" voice and has no background music (`"music": false`). It opens on the thumbnail and the problem as the hook, then the Stackle channel intro, then the rest of the episode, and closes on the comment ask. It is built with the shared kit in `../explained/` (see its README for the running order and the tools).

| Cut | File | For |
|---|---|---|
| Landscape | `stackle-video/graphics/spark-explained.mp4` (1920×1080) and `spark-explained.srt` | YouTube. Upload the `.srt` as captions |
| Vertical | `stackle-video/graphics/spark-explained-vertical.mp4` (1080×1920), captions burned in | TikTok, Instagram Reels, YouTube Shorts |

The script and fact sources are in `stackle-video/scripts/spark-explained.md`; the post copy is in `spark-explained-posts.md`.

## Rebuild

```bash
cd stackle-video/source/spark
./build.sh            # landscape + .srt
./build.sh vertical   # vertical
```

## The scenes

0. **Opening card** (0:00). The thumbnail.
1. **The problem, as the hook** (0:02).
   - A laptop opens `orders.csv` (a million rows) in a second.
   - The file becomes `all_orders/` and its size counts up to 2 TB. The memory bar fills red ("out of memory"), and the progress bar crawls ("about 9 hours").
   - The laptop moves aside, four machines appear, and the file splits into eight 250 GB slices that fly out to them.
   - "Apache Spark" lands in the middle, with lines out to every machine.
   - Then the channel intro (0:18).
2. **What it is** (0:30). The Spark lockup. The definition word by word, with "across many machines" highlighted (two chips in the vertical cut). Python, SQL, Scala, Java and R pop up as they are said. The timeline: 2009 UC Berkeley, 2010 open-sourced, 2014 top-level Apache project.
3. **The core idea** (0:47).
   - A grey table splits into eight coloured partitions.
   - `daily_sales.py` types in, line by line, as its steps are named. The status reads "Nothing runs yet".
   - The plan appears as dashed boxes (read → filter → groupBy → sum → write).
   - On "saving the output", the last line types in and the plan turns solid. All eight partitions then run at once, one task each, and tick off.
4. **Architecture** (1:08).
   - The driver (your code and the plan) breaks the plan into eight task chips.
   - The cluster manager appears (Kubernetes, YARN, standalone) and gives the driver executors on three workers.
   - The tasks fly to the executors, and each executor's memory shows "cached".
   - Worker 2 dies. Its three tasks go grey and re-run on Workers 1 and 3, "rebuilt from the plan".
   - The results land in `s3://shop/daily_sales/`.
5. **In short** (1:33). "We use Spark.", three takeaways, then "That's Apache Spark" and the closing title.
6. **Comment ask** (1:48). "What should I explain next?"
