# Apache Airflow, Explained in 2 Minutes (episode 01)

A 1:55 explainer on a white canvas, voiced by the ElevenLabs "Crispus Roshan" voice over an upbeat original beat, with motion graphics synced to every word. It opens on the thumbnail, then the Stackle channel intro, then the episode, and closes on the comment ask. It is built with the shared kit in `../explained/` (see its README for the running order and the tools).

| Cut | File | For |
|---|---|---|
| Landscape | `stackle-video/graphics/airflow-explained.mp4` (1920×1080) and `airflow-explained.srt` | YouTube. Upload the `.srt` as captions |
| Vertical | `stackle-video/graphics/airflow-explained-vertical.mp4` (1080×1920), captions burned in | TikTok, Instagram Reels, YouTube Shorts |

Both are 30 fps at -14 LUFS. The build also saves each cut's first frame (the opening card) as `<video>-thumbnail.jpg`. The script is in `stackle-video/scripts/airflow-explained.md`, the post copy in `airflow-explained-posts.md`.

## Rebuild

```bash
cd stackle-video/source && npm install
cd airflow && ./build.sh              # landscape + .srt, motion blur on (about 6 minutes on 4 cores)
./build.sh vertical                   # the vertical cut (about 8 minutes)
./build.sh /tmp/draft.mp4 --sub 1     # fast draft, no motion blur (works with `vertical` too)
```

## The scenes

0. **Opening card and intro** (0:00). The thumbnail, then the channel intro.
1. **The problem** (0:15). The 6 AM grid of pipeline runs, and the three questions: when, in what order, what if one fails.
2. **What it is** (0:31). The title, what Airflow is, "the right task, time and order", and 2014 → 2016 → 2019.
3. **DAGs** (0:45). A TaskFlow DAG in Python next to the graph it makes. Tasks run in order once the ones before them succeed.
4. **Architecture** (1:03). DAG files → DAG processor → metadata database ⇄ scheduler → executor → workers, with results flowing back. The web UI sits on top: runs, logs and a one-click retry.
5. **In short** (1:34). "We use Airflow", three takeaways and the closing title.
6. **Comment ask** (1:48). "What should I explain next?"

## The vertical cut

- Everything that matters sits between y 180 and 1430 and inside x 90–990, so TikTok's top tabs, the buttons on the right and the caption at the bottom never cover it.
- The architecture is re-drawn as a three-column grid (UI on top, the metadata database in the middle, workers along the bottom). The camera tours it inside a clipped window, so zoom-ins never run under the captions.
- Captions come straight from the word timings (`../explained/captions.js`).

## Changing things

- **New voiceover take or new script:** replace `audio/vo.mp3` and `audio/vo.transcript.json`, then rebuild both cuts. If you change the words, update the `at('word')` calls in `scene.js` and `vertical.js` that point at them.
- **Music level:** `MUSIC=0 ./build.sh` makes a version without the beat; `MUSIC=.3 ./build.sh` makes the beat louder.
- **New thumbnail:** replace the two files in `img/`, then rebuild.
